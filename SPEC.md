# ragite-demo spec

## Goal

Show what RAGite does in a few minutes, with no code to write: one command builds a SQLite file from freely licensed text, one command serves it with a search page and the full SQL interface.

## Decisions

- **D1 Datasette as the base.** Datasette loads SQLite extensions, so RAGite's `MATCH` queries run in its SQL views and JSON API. The demo adds canned queries (`app/metadata.yml`) and one custom page (`app/templates/pages/search.html`) that calls them; no own web server.
- **D2 Public interface only.** Every search is RAGite's hybrid `MATCH` on `docs` (documents) or `docs_chunks` (chunks); other queries use those two tables and the `ragite_*` functions. No vector-only or full-text-only mode and no queries against RAGite's storage tables (`docs_vec`, `docs_fts`, ...): they are not part of the RAGite 1.0 spec.
- **D3 Data.** SQLite documentation (public domain, a 74-page subset of the pinned doc archive), 20 Wikipedia articles (CC BY-SA 4.0, pinned revisions: SQLite and databases, plus retrieval-augmented generation, search and embeddings) and the RAGite docs (MIT OR Apache-2.0, pinned commit). Only freely licensed data; no benchmark sets.
- **D4 demo.db is built, not committed.** It is ~25 MB and rebuilt from pinned inputs in seconds. CI uploads it as an artifact with `DATA_SOURCES.md`.
- **D5 HTML cleaning before indexing.** Page chrome, navigation, scripts, styles, SVG diagrams, infoboxes, footnote markers and link-only sections are removed so chunks hold prose. Text is not rewritten, with three layout exceptions so RAGite does not cut near-empty chunks: each table row becomes one paragraph (cells joined by ` | `), each list whose items are all short (at most 100 characters, no nested blocks) becomes one paragraph (items joined by `; `), and Unicode spaces such as U+00A0 become plain spaces.
- **D6 Platform.** Linux x86-64 only, until RAGite ships other release binaries (pihme/ragite#35).
- **D7 License.** Code MIT; data keeps its own license.
- **D8 Examples.** `examples/` holds runnable SQL for the public interface. Read-only examples are also canned queries; writes are not, so the served `demo.db` cannot be changed from the browser.
- **D9 Search results: context and each passage once.** The `search` query (`app/metadata.yml`), and with it the search page, works in SQL on `docs_chunks` and `doc_info` only. A short hit (under 80 characters, usually a bare heading) gets the next chunks of the same document and section as context: chunks that start after it, whose heading path begins with the hit's heading path, and that have at least 40 characters; at most two, and only until the card holds 200 characters. Cards are then taken in score order from the best 60 hits, at most 20. Each displayed piece (the hit, and each context chunk) is a span of the document; a span counts as already shown when at least half of its length lies inside spans displayed by better cards of the same document. A hit is dropped when its own span is already shown (for example the paragraph under a heading card), when it is a short hit whose context is all shown already (a heading whose paragraph is on screen), or when its text, context included, equals a better card's text after trimming and lower-casing (the same sentence on two pages). Context that is already shown is left out of a kept card. Neighbouring pieces of a split paragraph share only RAGite's short overlap, so both stay. The `spans` column lists the displayed spans.
- **D10 Search page presentation.** The page shows the `search` rows as cards, five at first and five more per "Show more", all from the one request (at most 20 rows, D9). Source chips (all, SQLite docs, Wikipedia, RAGite docs) set the `collection` parameter; only the selected source is fetched, and results are kept per question and source. When a source is selected, the page explains the filter limit (pihme/ragite#49). Relevance is shown as a bar relative to the best card of the search, labelled Best match (the first card), Very close (at least 95 %), Close (at least 85 %) or Related; the raw RRF score is in the tooltip. A card whose score is above 1/61 is marked "meaning + keywords": with k = 60 only a passage found by both rankings can score that high. Query words are highlighted as whole words: a word must start with the term ("vacuum" marks `auto_vacuum` and `VACUUMs`, not `xvacuum`), and marks separated only by a space or hyphen merge. Each card links to the source, its `doc_info` row and its `docs_chunks` row (`chunk_id` from the `search` query).
- **D11 Look and feel without template overrides.** Datasette's own pages are restyled by one global stylesheet and one small script (`app/static/ragite-demo.css`, `ragite-demo.js`, via `extra_css_urls` and `extra_js_urls`); the only template is `pages/search.html`. No `base.html` override and no plugins, so Datasette upgrades need no template upkeep; the header navigation is added by the script, and without JavaScript the pages are the restyled Datasette pages. Dark only (`color-scheme: dark`): there is no light variant and no `prefers-color-scheme` switch. Fonts (Space Grotesk, Geist, Geist Mono, SIL OFL 1.1) are Latin subsets served from `app/static/fonts/` with their licences; no third-party requests. The footer keeps "Powered by Datasette". Asset paths are absolute (`/static/...`): the demo is served at the root, not under a `base_url` prefix.
