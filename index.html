ragite-demo

Search the SQLite docs and Wikipedia in your browser with ragite and Datasette, offline and in one SQLite file.

Get startedGitHubReadme

#What it is

ragite-demo is a small Datasette app that shows ragite at work. It indexes the SQLite documentation, five Wikipedia articles and ragite's own docs in one SQLite file and serves a search page next to Datasette's full SQL interface. Nothing runs on a server or calls an external service: the embedding model is built into the extension and runs on the CPU.

Type a question, optionally pick a source, and get passages with the document title, the heading path, the source link and a score. A very short hit, usually a bare heading, comes with the text that follows it, and each passage is shown once. Every search links to the same query as SQL.

#Current status

Last updated 17 October 2026 · main@ef4fbd9

The demo builds its database from pinned inputs in a few seconds: a subset of the SQLite documentation, five Wikipedia articles and the ragite documents, each checked against a fixed checksum or revision. Datasette serves a search page and canned queries that use only ragite's public interface. A short hit such as a bare heading comes with the text that follows it, and each passage is shown once. Runnable SQL examples show how to create a table, insert documents and search documents or chunks. Continuous integration builds the database, runs the tests, the examples in the command-line shell, a smoke test over HTTP and a browser check of the search page. There is no release yet.

The demo runs on Linux x86-64 only, because ragite publishes release binaries for that platform alone so far, and it needs about 165 megabytes of disk, most of it for the extension with its built-in model. The database is not committed and has to be built first. The source filter can miss matching passages, since ragite picks its best candidates from all sources before the filter applies; the search page warns about it. Headings are still chunks of their own in ragite, so very short hits remain possible. The served database is read-only, and nothing runs on a public server: the demo is meant to be run locally. No issues are open.

#Quickstart

git clone https://github.com/pihme/ragite-demo.git
cd ragite-demo
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
scripts/build-demo-db        # downloads libragite.so and the pinned sources, builds app/demo.db
datasette serve app --load-extension ./libragite --port 8001
# open http://127.0.0.1:8001/search

#Search with SQL

The demo uses only ragite's public interface: the Document table, its _chunks companion and the ragite_* functions. The examples/ folder has runnable SQL for creating a table, inserting each format, searching documents and chunks, and embedding text.

SELECT i.title, c.chunk, c.score
FROM docs_chunks c JOIN doc_info i ON i.doc_id = c.doc_id
WHERE docs_chunks MATCH 'How do I change the output mode of the sqlite3 shell?'
LIMIT 5;

Source filter. ragite picks its best candidates from all sources before the filter applies, so a narrow source can return few or no passages (ragite#49). The search page says so when a filter is active.
